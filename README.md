#### Запуск без Docker (разработка)
Нужен Python 3.14 и [uv](https://docs.astral.sh/uv/). Зависимости описаны в `pyproject.toml`, точные версии зафиксированы в `uv.lock`.
```bash
uv sync                          # создать .venv на Python 3.14 и поставить зависимости из uv.lock
uv run alembic upgrade head      # применить миграции
uv run python main.py            # запустить бота
```
Добавить или обновить зависимость: `uv add <пакет>` / `uv lock --upgrade-package <пакет>`, затем закоммитить `pyproject.toml` и `uv.lock`.
Docker-образ ставит зависимости через `uv sync --locked`: сборка упадёт, если `uv.lock` не соответствует `pyproject.toml`.

Тесты (без БД, Redis и Telegram): `uv run python -m unittest discover -s tests -t .`

### Производственный календарь

---
Даты в `calendar_dates` вручную вносить не нужно. При старте бота и каждую ночь (`CALENDAR_SYNC_JOB_HOUR`:`CALENDAR_SYNC_JOB_MINUTES` в `config.py`, по умолчанию 04:10 МСК) бот загружает текущий и следующий год из [isdayoff.ru](https://isdayoff.ru) — с праздниками, переносами и рабочими субботами.

- Если isdayoff.ru недоступен или ещё не знает год (постановление о переносах выходит осенью), недостающие дни добавляются по библиотеке `holidays` (праздники и переносы РФ, без рабочих суббот). Когда данные появятся на isdayoff.ru, они заменят эти дни.
- Источник дня — `calendar_dates.source` (`CalendarSource` в `src/dto/calendar_dates_dto.py`): `0` — isdayoff.ru, `1` — holidays.
- Прошлые дни и сегодня не меняются, `visit_count` синхронизация не трогает.
- В чат алертов (`TG_ALERTS_CHAT_ID`) приходят уведомления: календарь изменился; день стал нерабочим, а на него есть брони (брони не отменяются); isdayoff.ru не отвечает больше 3 дней; в декабре ещё нет данных на следующий год.
- Уведомления отправляет `AlertService` (`src/services/alert_service.py`), подробнее — в разделе «Алерты».

### Шаблоны листов в Google-таблице

---
Бот сам создаёт листы месяцев («ноябрь 2026») в таблице посещений `GOOGLE_SHEET_KEY` — на текущий и два следующих месяца, то же окно, куда `sheet_update_job` пишет отметки. Запуск: при старте бота (в фоне) и каждую ночь (`SHEET_TEMPLATE_JOB_HOUR`:`SHEET_TEMPLATE_JOB_MINUTES`, по умолчанию 04:30 МСК). Код: `src/use_cases/sheet_template_use_case.py`, раскладка листа — `src/utils/sheet_template.py`.

Данные не перезаписываются. Готовый лист помечается developer metadata `bot_v5_template`, и дальше бот его не меняет:

| Лист месяца | Что делает бот |
|---|---|
| нет | создаёт шаблон |
| есть, с меткой бота | ничего; если лист расходится с производственным календарём — алерт |
| есть без метки, даты совпадают с месяцем (создан раньше скриптом) | ставит метку |
| есть без метки, совсем пустой — ни шапки, ни данных (создание оборвалось) | удаляет и создаёт заново |
| есть без метки, даты не те, но лист не пустой (данные или другая раскладка) | не трогает, алерт |

- Раскладка листа — как в прод-таблице, на неё рассчитан Apps Script (`doPost`): A — Продукт, B — Должность, C — ФИО, даты с D, закреплены 4 строки и 3 колонки, A1:C1 объединены. Скрипт объединяет A1:C1 при каждой записи, поэтому лист с одной закреплённой колонкой он записать не может («Нельзя объединять закрепленные и незакрепленные столбцы»). Менять раскладку можно только вместе со скриптом.
- Лист создаётся, только когда все дни месяца пришли из isdayoff.ru. Если до месяца меньше 7 дней, а данных всё нет, лист собирается по библиотеке `holidays`, и приходит предупреждение.
- Нерабочие дни (серые, без формулы в строке 4) — по `calendar_dates.is_workday`, поэтому рабочие субботы учтены. Верх градиента в строке 4 — лимит дня из `office_capacity_weekdays`.
- Без `GOOGLE_SHEET_CREDENTIALS` и `GOOGLE_SHEET_KEY` задача ничего не делает.

### Алерты

---
Все алерты бот отправляет в чат `TG_ALERTS_CHAT_ID` (`.env`):
- **Ошибки из логов** — любая запись уровня ERROR и выше (`src/infrastructure/log_alerts.py`). Алерт содержит сообщение, хвост трейсбэка, файл и строку. Повторы с одного места в коде (файл, строка и тип исключения) приходят не чаще раза в час, даже если текст ошибки меняется.
- **Производственный календарь** — см. раздел выше.
- **Перезапуск после сбоя** — прошлый запуск закончился без штатной остановки: падение, нехватка памяти, перезагрузка сервера (`src/infrastructure/ops_alerts.py`). Бот раз в минуту пишет в Redis метку `bot:heartbeat`, при штатной остановке — `bot:stopped_at`.
- **Пропущенные задачи планировщика** — запуски cron-задач (дайджест, напоминания, отмена неподтверждённых броней), которые пришлись на время, пока бот не работал, или были пропущены, потому что бот был занят дольше `misfire_grace_time`. Такие запуски сами не повторяются.

Обычные ответы Telegram «message is not modified» и «query is too old» алерта не вызывают: они пишутся в лог как WARNING (`src/utils/telegram_errors.py`).

Бота нужно добавить в этот чат, и у него должно быть право писать сообщения. Иначе алерты не дойдут, а в логе будет WARNING.

Отправить свой алерт: `await alerts.notify(Alert("Заголовок", "текст", level=logging.ERROR, key="ключ-повтора"))`, где `alerts: AlertService` берётся из контейнера. Алерты с одинаковым `key` отсекаются (метка в Redis), для синхронного кода есть `notify_nowait()`.

### Виджеты выбора места (Bot API 10.4)

---
Календарь со схемой зала в личном чате и дайджест со схемой в группе работают на HTML-виджетах Telegram.
По умолчанию выключены: бот работает как раньше, но каждой новой брони уже выдаётся номер места.

```bash
# .env
WIDGETS_ENABLED=true          # «Забронировать место» и бронь за сотрудника открывают виджет, «Мои брони» скрыта из меню
DIGEST_WIDGET_ENABLED=true    # дайджест в группе уходит виджетом
WIDGET_HISTORY_MONTHS=3       # сколько прошлых месяцев можно листать в календаре (только просмотр)
WIDGET_FUTURE_MONTHS=0        # сколько месяцев после текущего можно листать вперёд; бронь всё равно только
                              # на PAGINATION_LIMIT_WEEKS недель, дальние дни серые (0 — до конца окна бронирования)
# Методы виджетов пока есть только на бете Bot API (обычный токен подходит):
TELEGRAM_API_BASE=https://api.telegram.org/beta
```

- Миграция `e1a7c3f9b2d4` добавляет `bookings.seat_no` и раздаёт места будущим броням по порядку записи: `alembic upgrade head`.
- Схема зала, подпись кабинета и место руководителя: `src/ui/widgets/layout.py`. Шаблоны виджетов: `src/ui/widgets/*.html` (≤ 4096 байт после zlib).
- При старте бот проверяет, есть ли методы виджетов на этом адресе. Если нет, в логе будет подсказка, а бот покажет старые экраны и отправит дайджест текстом.
- Тестовые брони в локальной базе: `uv run python scripts/dev_seed_bookings.py` — сценарии на ноябрь и прошлые дни за `WIDGET_HISTORY_MONTHS`; `--only-past` — только прошлые дни.
- Запросы из виджетов приходят апдейтом `widget_query`, его перехватывает `WidgetQueryMiddleware` (aiogram пока не знает этот тип).
- Отправить дайджест сразу, не дожидаясь 16:00 (только для администраторов, в личке с ботом): `/digest_now` — на ближайший рабочий день, `/digest_now 10.11` — на дату.
- Тесты виджетов входят в общий набор тестов (см. выше).
